# Unity Burst & Job System Performance Benchmark

Unity의 **Burst Compiler**와 **Job System**을 활용하여 데이터 지향 설계(Data-Oriented Design)의 성능 이점을 실증하는 벤치마크 프로젝트입니다. 100만 개의 복잡한 수학 연산(`sqrt`, `sin`, `cos`, `log`, `exp`)을 처리하며 각 최적화 단계별 성능 차이를 측정합니다.

## 📊 벤치마크 결과
**테스트 환경:** 1,000,000개 데이터 연산 (라이젠 7 2700X / 32GB RAM)

| 방식 | 설명 | 소요 시간 | 성능 향상(vs Normal) |
| :--- | :--- | :---: | :---: |
| **Normal** | 단일 스레드 (객체지향 방식) | **248 ms** | - |
| **Burst Only** | 단일 스레드 + Burst 컴파일 | **62 ms** | 약 4배 |
| **Job Only** | 멀티 스레드 (Job System) | **18 ms** | 약 14배 |
| **Burst + Job** | **멀티 스레드 + Burst 최적화** | **5 ms** | **약 50배** |

*측정 결과는 하드웨어 및 실행 환경에 따라 차이가 있을 수 있습니다.*

## 🚀 분석 결과 요약
1. **Burst Only (62ms)**: 단순히 연산 로직을 LLVM 기반의 기계어로 최적화하는 것만으로도 기존 대비 약 4배의 속도 향상을 확인했습니다.
2. **Job Only (18ms)**: CPU의 멀티 코어를 활용한 병렬 처리는 단일 스레드 대비 압도적인 효율을 보여줍니다.
3. **Burst + Job (5ms)**: 연산 최적화(Burst)와 병렬 처리(Job System)가 결합되었을 때, 하드웨어의 물리적 한계에 근접하는 최상의 성능을 기록했습니다. 

## 💡 결론
이 결과는 **데이터를 연속적으로 배치하고(Data-Oriented), CPU의 연산 파이프라인을 최적화(Burst)하며, 다중 코어를 활용(Job System)하는 방식**이 현대 게임 엔진에서 왜 필수적인지 명확히 증명합니다. 단순한 로직 변경만으로도 프로그램의 성능을 수십 배 개선할 수 있음을 확인하였습니다.


## 🔍 성능 향상의 기술적 원리 (왜 248ms에서 5ms가 되었는가?)

단순한 로직 변경이 아닌, **CPU의 물리적 한계를 극복하기 위한 하드웨어 친화적 설계**가 성능 개선의 핵심입니다.

### 1. 데이터 지역성(Data Locality)과 연속적 메모리 배치
* **Normal (248ms):** 객체지향 방식은 힙(Heap) 영역에 객체들이 산발적으로 흩어져 있습니다. CPU가 데이터를 가져올 때마다 주소를 찾아 헤매는 **'포인터 체이싱(Pointer Chasing)'**이 발생하며, RAM 접근 대기 시간으로 인해 엄청난 병목이 발생합니다.
* **Burst + Job (5ms):** 데이터를 `NativeArray`와 같은 연속된 메모리 공간에 줄 세웠습니다. CPU는 데이터를 순차적으로 읽어 들일 때, 다음 데이터까지 미리 가져오는 **'프리페치(Prefetch)'**가 가능해지며, RAM 접근 횟수를 최소화합니다.

### 2. 캐시 히트(Cache Hit)율 극대화
* CPU는 RAM보다 훨씬 빠른 '캐시 메모리'를 가지고 있습니다.
* 데이터가 인접해 있으면, 한 번의 메모리 로드로 여러 개의 데이터가 캐시에 한꺼번에 올라옵니다. [Burst + Job] 방식은 이 캐시를 최대한 활용하여 CPU가 데이터가 오길 기다리는 **'스톨(Stall)' 현상**을 거의 완벽하게 제거했습니다.

### 3. SIMD(Single Instruction, Multiple Data) 최적화
* **Burst Compiler**는 일반적인 C# 코드를 LLVM 최적화를 거친 기계어로 변환합니다.
* 특히 **SIMD(벡터화)** 기술을 통해, 하나의 CPU 명령어가 1개의 데이터가 아닌 4개, 8개의 데이터를 동시에 연산하도록 최적화합니다. 연산량이 많은 `sin`, `cos` 등의 함수에서 이 효과가 극대화되어 성능을 수십 배 끌어올렸습니다.

### 4. 멀티코어 병렬 처리 (Job System)
* 8코어(Ryzen 7 2700X)의 자원을 최대한 활용하여 100만 개의 데이터를 여러 코어가 나누어 처리했습니다. 
* 단순히 연산 속도만 빨라진 것이 아니라, 병렬 스케줄링을 통해 CPU가 쉬는 시간을 없애 전체적인 처리량을 극대화했습니다.

**결론적으로, 하드웨어 아키텍처(CPU/RAM 통신 물리 법칙)에 맞춰 데이터를 배치하고 연산 구조를 재편한 것이 50배 성능 향상의 비결입니다.**
